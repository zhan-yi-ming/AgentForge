## 背景

AgentForge 已具备项目 RAG、Tool Intent、权限审批和可恢复执行，但目前只有零散单元测试，没有固定数据集、统一 runner 和可比较的真实评测报告。V2-08 建立可在本地与 CI 重复执行的离线 Evaluation Pipeline，为 V2-09 Release Gate 提供稳定输入。

## 目标

- 固定覆盖 Wiki、Task、Tool 参数和 no-tool 的小型版本化数据集。
- 提供 RAG、Answer、Tool/Agent 三类可执行 runner，并输出机器可读 JSON 报告。
- 报告 Recall@K、MRR、Hit Rate、Faithfulness、Tool Selection Accuracy 与 Task Success Rate。
- 默认 subject 真实调用当前 BM25/RRF 排序和生产 `plan_tool`，不把 gold 传给被测逻辑。

## 非目标

- 不实现 V2-09 完整回归或发布门禁。
- 不新增业务 Tool，不修改 RBAC、Risk、Approval、Checkpoint、生产数据库或公共 HTTP 契约。
- 不用离线词项支持代理指标冒充 LLM 语义裁判，也不在真实运行前向 README 填入数字。

## 设计决定

- 数据集将 input、corpus 与 gold 分离；subject 只接收 input/corpus，评分器才读取 gold。
- RAG 以 source ID 为评测单位，避免 chunk 数量改变扭曲 gold；默认 subject 在固定语料上执行现有 BM25 与 RRF。
- Tool Selection Accuracy 检查期望工具或 no-tool；Task Success Rate 进一步要求完整规范化参数一致，不能只比较工具名。
- Faithfulness 是离线、确定性的 claim-to-context 词项支持率。它适合回归而不是语义正确性证明，报告必须携带 metric method 和限制。
- 报告包含 dataset hash、生成时间、逐样本结果和宏平均指标；时间不参与可重复性断言。

## 实现

- 新增 `agentforge_agent.evaluation` package：严格 dataset loader、RAG/Answer/Tool 指标、当前代码离线 subject、统一 runner、原子 JSON report writer 与 CLI。
- 当前 subject 使用生产 `HashEmbeddingProvider`、`bm25_rank`、`reciprocal_rank_fusion` 和 `plan_tool`；RAG 在 source 级固定 corpus 上离线运行，不连接生产数据库或 Core API。
- 新增 `evaluation/datasets/v2-small.json`：6 个 Wiki/Task source、4 个 RAG case、3 个 Answer case、4 个 Tool case，覆盖多 gold、显式 no-hit 信号、Create/Update 完整参数和 no-tool。
- 新增真实 `evaluation/reports/v2-baseline.json`：dataset SHA-256、方法/限制、聚合指标和逐 case ranking/claim/proposal 证据。
- README 与 Agent Service 运行说明只发布真实小数据集结果，并明确 Faithfulness 和样本规模限制。

## 风险与回滚

主要风险是 gold 泄漏、指标定义错误、把检索和回答评测混淆，以及报告因运行环境漂移不可比较。回滚可删除独立 evaluation package、dataset、runner/report 和对应文档，不涉及生产数据迁移。
