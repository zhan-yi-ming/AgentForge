## 背景

AgentForge 已由 Java 集中管理 Tool Policy、RBAC、Approval、Idempotency 与 Audit，但外部 Agent 只能理解产品私有 HTTP 契约。V3-01 增加标准 MCP Adapter，使调用方可以发现和调用 Wiki/Task Tool，同时不能绕过现有确定性业务边界。

## 目标

- 通过 MCP Streamable HTTP 暴露 `search_wiki`、`get_task`、`create_task`、`update_task`。
- MCP 读操作复用 Java Application Service；写操作只创建 `PENDING` Approval，人工确认后才复用既有执行链路写数据库。
- 保持 Project/User 隔离、服务端 Tool Metadata、参数校验、错误契约、审批重放与幂等语义。

## 非目标

- 不实现 MCP Resources、Prompts、Sampling、客户端或 OAuth Authorization Server。
- 不让 MCP 直连数据库，不允许 MCP 参数决定 actor、role、risk 或 approval 状态。
- 不实现 V3-02 Model Gateway、V3-03 Multi-model Routing 或后续 GraphRAG。

## 设计决定

使用官方 Java SDK 2.0.1 支持的 MCP `2025-11-25` Streamable HTTP。2026-07-28 是当前最新规范，但 Java SDK 的当前稳定线尚未支持；本节点不实现自定义半兼容协议。HTTP 使用现有 AgentForge Bearer JWT，首版属于预配置凭据模式，不宣称完整 OAuth 自动发现。

MCP 写操作创建 `source=MCP`、无 conversation/checkpoint 的 Approval。`create_task` / `update_task` 返回 pending action，不能在同次调用中写 Task；后续人工 confirm/reject 继续使用既有公共接口。Chat Action 保持 `source=CHAT`、conversation 与 LangGraph resume 语义。

## 实现

- Core API 通过官方 Java MCP SDK 2.0.1 在 `/mcp` 提供无状态 Streamable HTTP Server，固定暴露四个 Tool，并以 JSON Schema 拒绝未知字段、非法 UUID、超长文本和负版本。
- Servlet 从现有 Spring Security JWT 上下文提取 `AuthenticatedActor`；客户端参数不能注入 actor、role、risk 或审批状态。读 Tool 复用 `WikiPageService` / `TaskService`。
- `AgentTaskAction` 新增可信 `source=CHAT|MCP` 与 MCP 提案幂等键；V11 迁移回填既有行为为 CHAT，并允许 MCP Action 不绑定 conversation/workflow。MCP 写 Tool 首次只创建 PENDING Action 和 REQUESTED Audit；重试复用原 Action 当前状态，不重复追加 REQUESTED Audit。
- 既有 confirm/reject HTTP 路径按 null workflow 识别 MCP Action，不调用 Python resume；confirm 继续执行权限、Risk、版本及 Idempotency 检查后才写 Task。
- Web Nginx 与生产 TLS Gateway 都增加精确 `/mcp` 反向代理；生产入口沿用 API 限流并关闭响应缓冲。

## 风险与回滚

主要风险是 SecurityContext 丢失、跨项目 IDOR、写 Tool 绕过 Approval、MCP/Chat Action 混淆、schema drift 与错误泄漏。回滚时撤销应用提交；数据库迁移必须保持向后兼容，不能修改已执行迁移。
