# Pi 提交前审核与连接方式治理

- 状态：Implemented
- 日期：2026-09-06
- 范围：项目治理、提交前门禁、Pi 启动器发现与一次性只读审核

## 背景

仓库现有治理文档同时保留了“停用 Pi”和“恢复一次性 Pi 审核”两种表述，容易让 Codex 在提交前采用错误门禁。当前 Codex 进程运行裸 `pi.cmd --list-models v4-pro` 时还出现启动器找不到；历史成功方式实际是直接调用已知的 `pi.cmd` 绝对路径，而不是依赖未继承该目录的 PATH。

## 目标与范围

- 删除现行治理中的“禁止调用 Pi 审核”表述，明确 Pi 只负责实现和 Codex 测试完成后的独立只读审核。
- 明确所有代码、配置、脚本和文档变更在创建提交前都必须通过一次 Pi 审核；只有用户对本次变更明确豁免时才可跳过，并必须记录。
- 新增唯一连接指南：优先读取 `AGENTFORGE_PI_CMD`，其次查找 PATH 中的 `pi.cmd`；两者均失败时立即请用户设置路径，不进行全盘搜索、安装尝试或循环重试。
- 固定模型为 `deepseek/deepseek-v4-pro`，固定使用一次性 `run-review.ps1`，不恢复 monitor、validation 或自动阶段推进。
- 记录用户持续授权：代码和文档完成、Codex 测试与敏感信息扫描通过后，可直接把本阶段源码、配置、测试和文档 diff 发送给 DeepSeek Pi V4-pro 并触发审核，无需逐次询问。

不在范围：安装或升级 Pi、修改 Pi 账号、恢复后台 monitor、让 Pi 执行测试、在仓库中保存个人绝对路径，或向 Pi 发送 `.env`、真实密钥、Token、私钥及认证凭证内容。

## 验证方式

1. 复现当前进程中环境变量和 PATH 都找不到 `pi.cmd` 的失败信号。
2. 使用历史成功启动器的已知绝对路径执行 `--list-models v4-pro`，确认返回完整模型选择器。
3. 检查治理文档和 `AGENTS.md` 不再把当前一次性审核描述为禁用，并包含提交前门禁及快速失败规则。
4. 对修改的 Markdown 和 PowerShell 引用执行 `git diff --check`、链接/路径存在性检查和敏感信息扫描。
5. 提交前使用确认可用的启动器执行一次 Pi 只读审核；若 Pi 登录、额度、模型或环境失败，立即交给用户处理。

## 回滚思路

若一次性审核入口不可维护，可恢复本次治理文档和 `AGENTS.md`，但不得恢复自动 monitor 或让 Pi 替代 Codex 测试。个人启动器路径只保存在用户环境变量中，回滚仓库文件不会改变用户机器配置。

## 初始诊断证据

- 当前 Codex 进程：`AGENTFORGE_PI_CMD` 未设置，PATH 中无 `pi.cmd`；最小复现退出码 127。
- 历史成功启动器文件仍存在；直接使用其已知绝对路径运行 `--list-models v4-pro`，退出码 0，并返回 `deepseek/deepseek-v4-pro`。
- 根因是 Codex 进程未继承 Pi 启动器目录，而不是 DeepSeek V4-pro 不可用。

## 实施与验证回填

- 新增 `docs/06-operations/pi-review-connection.md`，统一持续授权、启动器配置、十秒预检、提交前审核和快速失败规则。
- 更新变更流程、完成标准、测试策略、审核中心、功能/运维索引和 bridge README；现行规则不再把一次性 Pi 审核描述为禁用，历史 monitor/validation 仍明确停用。
- 更新根 `AGENTS.md`：所有代码、配置、脚本和文档变更都在提交前触发 Pi；持续授权无需逐次询问；敏感凭证不进入审核输入；连接失败只检查环境变量和 PATH 后立即请用户介入。
- 已把经过验证的启动器绝对路径写入 Windows 用户级 `AGENTFORGE_PI_CMD`，未把个人路径提交到仓库。用户环境变量写入与回读一致。
- 使用该用户环境变量运行 `--list-models v4-pro`，退出码 0；真实目录表在 provider/model 两列返回 `deepseek` 与 `deepseek-v4-pro`，审核使用的完整选择器为 `deepseek/deepseek-v4-pro`。未读取或输出登录凭证。
