# 基于风险的验证与审核机制

- 状态：Implemented
- 日期：2026-09-06
- 适用范围：V1.2 收口及后续 V2/V3 开发节点

## 背景

原规则把所有代码、配置、脚本和文档修改都视为同一验证成本：默认全量测试并在每次提交前执行 Pi 审核。这能避免漏检，但会让纯文案、CSS 等低风险调整重复消耗时间与外部模型 Token；另一方面，连续跳过检查的小改动又可能累积偏航。

## 目标与范围

- 保留不可跳过的文档先行和真实证据链，每次修改仍必须进入独立变更记录或当前同主题记录。
- 依据“出错时最大影响范围”将修改分为 L0–L3，不依据代码行数评级。
- L0/L1 使用最小充分验证并默认跳过 Pi；L2 使用模块测试、核心 smoke 和增量 Diff Review；L3 使用全量测试、核心回归和 Pi Review。
- 连续 5 次 L0/L1、开发节点结束、重要 merge/commit 前、进入下一节点前、低风险修改扩散到多模块或测试出现异常时，强制执行一次全量回归和 Milestone Review。
- Pi 分为 Diff Review 与 Milestone Review；普通 Diff Review 不无故扩大到全项目重设计，只有“必须修改”阻塞交付。
- 每次交付明确报告风险等级、修改范围、可能影响、已执行验证、未执行项及原因。

## 非目标

- 不降低权限、安全、数据、Agent 状态机、API 契约和跨模块修改的门禁。
- 不允许以风险评级代替证据，不允许把未知影响强行评为 L0/L1。
- 不恢复 Pi 测试、monitor、自动阶段推进或 Flash 降级。
- 不取消节点级全量回归，也不允许无限累计跳过大检查。

## 风险与升级

- L0：文案、CSS、注释、README、无行为格式整理；执行必要语法、类型、lint 或构建检查。
- L1：单组件、小函数、局部交互、接口不变且影响明确的修复/重构；执行直接相关测试，必要时加核心 smoke。
- L2：API 业务逻辑、数据库查询/写入、缓存、Tool Calling、Agent 节点、Workflow、状态变化、外部服务或多文件/多模块修改；执行相关模块测试和核心 smoke，并做 Pi Diff Review。
- L3：架构、Schema/迁移、权限/安全/额度/限流、Agent Runtime/状态机、全局上下文、核心 Workflow、API Contract、公共基础模块或多模块重构；执行完整测试套件、核心业务回归和 Pi Review。
- 公共函数/共享结构/API 入参与返回/数据库字段/Agent 状态/权限安全额度限流/异常重试超时/多模块/影响不明中的任一项，至少 L2；命中 L3 类别直接 L3。

## 累计记录

每份变更记录写明风险等级和是否增加低风险累计计数。L2/L3 Review 或 Milestone Review 通过后计数归零。连续第 5 次 L0/L1 不再按低风险收口，必须升级为里程碑门禁。节点边界和重要合并不依赖计数，始终触发完整门禁。

## 实现计划

1. 更新变更流程、完成标准、测试策略、审核中心和 Pi 连接文档。
2. 更新项目级 `AGENTS.md`，把风险评估作为修改后的固定决策点，并调整 Pi 强制规则。
3. 给 Pi 审核入口增加 Diff/Milestone 模式及显式上下文文件；更新 Reviewer 提示词，只让明确的“必须修改”阻塞。
4. 对 PowerShell 脚本做解析检查、差异格式和敏感扫描；本次 V1.2 是跨模块节点收口，仍执行 Milestone Review。

## 回滚

恢复本次治理文档、`AGENTS.md` 和审核脚本/提示词即可回到每次提交统一全量测试与 Pi 审核；不涉及产品数据、数据库或线上运行配置。
