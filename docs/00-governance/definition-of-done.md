# 完成标准

- 状态：Accepted

一项变更只有同时满足以下条件才算完成：

- 变更记录存在，且背景、范围、实现和验证不是空白。
- 受影响的产品、架构、功能、API、开发或运维文档已经先更新。
- 重要取舍已经写入 ADR。
- 实现没有超出文档声明的范围。
- 新增或变化的行为有相称的自动化测试；无法测试的部分有原因和人工验证方法。
- 已分别记录 L0–L3 风险评级、影响域、规划器输出与最小充分验证选择；L3 只有在 Release Gate、全仓共享变化或影响无法收敛时要求全仓测试。
- 测试由 Codex 亲自执行。同一任务内只有相关输入与 base 未变化的结果可以复用；跨任务历史报告或旧缓存不能宣称当前通过。
- 构建与测试结果、退出码、测试数量、失败/跳过项及测试数据清理结果按真实情况写入变更记录。
- 日志和错误信息足以定位失败环节，且不泄漏敏感信息。
- 配置通过环境变量或显式配置提供，不把密钥写进仓库。
- 公开仓库敏感信息扫描已通过，或已真实记录无法运行的原因和人工检查范围。
- L2/L3 或累计/节点触发时，创建提交前已通过相应的 DeepSeek Pi V4-pro Diff/Milestone 只读审核；L0/L1 跳过时已记录原因与累计计数。若用户针对本次应审核变更明确豁免，变更记录已写明豁免事实和原因。
- 文档链接、目录和命令可用，未来状态与已实现状态没有混写。
- 已创建表达本阶段完整意图的 Git 提交。
- 已把该提交推送到确认的远程分支并核验远程引用；推送失败时不得视为完成。
- 提交与推送之间没有新的文件改动；远端引用已核验并完成当前变更汇报。
- V2/V3 下一 Node 尚未开始并等待新的用户确认；已由用户明确授权和排序的独立非 Node 后续任务必须使用新变更记录与独立提交。

## 2026-09-06 生效：Pi 审核不替代测试

Pi 只负责提交前一次性只读审核；Codex 直接运行构建、格式和测试，核对机器产物并记录退出码、测试数量、失败、跳过与清理。Pi PASS 不能替代机器测试，旧 monitor、validation 与自动阶段推进不得恢复。
