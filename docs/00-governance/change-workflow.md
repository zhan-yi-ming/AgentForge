# 标准变更流程

- 状态：Accepted

## 1. 建立上下文

阅读产品范围、架构、相关功能、API、ADR 和最近变更。确认当前阶段允许做什么，防止提前引入 V2/V3 能力。

## 2. 写变更记录草稿

在 `docs/07-changes/` 创建记录，至少先填背景、目标、范围、非目标、计划修改的文档和实现。此时状态为 `Proposed`。

## 3. 先写目标状态文档

根据变更类型更新功能、API、架构、数据、开发或运维文档。文档必须把关键取舍讲清楚；复杂设计先新增 ADR。

## 4. 实现

只实现已经写进文档的范围。发现设计需要变化时，暂停实现，先回到步骤 2 或 3 更新文档。

## 5. 验证

Codex 先按“出错时最大影响范围”评为 L0–L3，再选择最小充分验证，不以代码行数判断风险。L0 做必要语法/类型/lint/构建检查；L1 做相关测试和必要 smoke；L2 做相关模块测试与核心 smoke；L3 做全量测试与核心回归。公共函数、共享结构、API、数据库字段、Agent 状态、权限/安全/额度/限流、异常/重试/超时、多模块或影响不明的修改至少 L2，命中架构、Schema、安全、状态机、公共契约等高风险项则为 L3。

Codex 亲自执行选定门禁并清理由本次测试明确创建的临时数据。失败时先建立可重复信号、记录证据，再按文档先行和 TDD 纵向切片修复；不得用旧缓存、历史报告或模型文字结论代替当前机器结果。

## 6. 回填证据

Codex 把实际文件、接口、迁移、测试命令、退出码、数量、失败/跳过、清理结果和偏离原计划之处写回变更记录。将相关文档状态更新为 `Implemented`。

## 7. 风险匹配的 Pi 只读审核

L0/L1 默认不调用 Pi；L2 在相关测试与 smoke 后执行增量 Diff Review；L3 执行 Pi Review。连续 5 次 L0/L1、开发节点结束、重要 merge/commit、进入下一节点前、低风险修改扩散到多模块或测试异常时，强制执行全量测试、核心 smoke 和 Milestone Review，累计计数归零。Pi 不运行测试、不修改文件、不启动 monitor，也不自动推进阶段。连接方式和快速失败规则见 `../06-operations/pi-review-connection.md`。

只有用户针对本次变更明确豁免时才可跳过；豁免原因必须写入变更记录。Pi 登录、额度、启动器、模型或环境失败时立即请用户处理，不得全盘搜索、安装尝试、Flash 降级或循环重试。

## 8. 创建阶段提交

AI 在确认文档已回填、验证结果真实且工作区只包含本阶段变更后，创建一个真实、可读的 Git 提交。提交信息应表达本阶段的完整意图，不能把下一阶段工作混入当前提交。

## 9. 推送当前提交

提交成功后不得再修改文件，也不得运行下一阶段命令；唯一允许的交付动作是把刚创建的提交推送到事先确认的远程分支，并用远程引用核验 commit。禁止 force push，远程存在意外历史时立即停止并报告。

提交信息标题表达阶段意图，正文至少概括文档、行为 / 接口、数据迁移、安全影响、验证结果和已知限制。变更记录提供详细上下文，Git 远程引用提供实际 commit / push 事实，不在仓库文件内伪造无法自指的 commit hash。

## 10. 推送后强制中断

推送核验成功后，AI 必须立即停止开发。最终汇报包含：

1. 本阶段已经完成的内容。
2. 已运行验证、未通过或未运行项及原因。
3. 用户可以介入的事项，并明确哪些是必需、哪些只是建议。
4. 下一阶段的目标、文档先行项、实现步骤、验证方式和明确非目标。

只有用户明确确认下一阶段计划后，AI 才能开始下一阶段。若提交成功但推送失败，也必须停下并报告，不得借机开始新实现。若用户提出修改意见，先更新计划；确认前不实现。

## 小改动如何处理

拼写修正或同一主题内的轻微整理，可以更新当前变更记录，不必机械地一字一记录。但只要行为、接口、配置、数据或目录发生变化，就必须有对应证据。

同一大版本或同一阶段内发现的非阻断问题采用批量闭环：Codex 一次性完成相关文档与整批实现，再统一审查和全量测试。不要为单个轻微问题重复创建独立变更记录或提交循环。只有安全漏洞、数据破坏风险、架构级决策或阻塞后续开发的问题才立即单独中断处理。

同主题轻微变更仍在当前记录中逐项留下范围和验证证据，并增加 L0/L1 累计计数。未命中累计或节点触发条件时可以不做 Pi；纯文档变更按实际范围执行文档一致性、路径、格式和敏感信息检查，不虚构不适用的代码测试。

每次完成修改后必须报告：风险等级、修改范围、可能影响、本次验证、未执行项及原因。L2/L3 不得为了节省时间主动降级门禁；影响范围无法确认时自动升级为 L2。

## 2026-09-06 生效：提交前一次性 Pi 审核

Pi 仅恢复为提交前一次性只读代码审核；Codex 仍是唯一测试执行者。旧 monitor、validation 和自动阶段推进保持停用。详见 `../06-operations/pi-review-connection.md`。
