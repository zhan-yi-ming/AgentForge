# 公开仓库安全制度

- 状态：Accepted
- 适用范围：源码、文档、Git 历史、Issue / PR、CI 日志和发布附件
- 仓库：`github.com/zhan-yi-ming/AgentForge`

## 不可提交的内容

任何环境都禁止提交真实的密码、JWT 签名密钥、API Token、云访问密钥、SSH / TLS 私钥、数据库生产连接串、Cookie、个人数据或包含这些内容的日志与截图。代码注释、测试夹具、文档示例和已删除但仍在 Git 历史中的文件同样属于公开范围。

`.env.example` 只允许包含公开、无权限的本地开发示例值或明显占位符。`.env`、私钥、日志、构建产物和本地数据必须由 `.gitignore` 排除。真实配置通过本机环境变量或 GitHub Actions Secrets 注入；云环境优先使用短期身份或 OIDC，避免长期静态密钥。

## 提交前检查

1. 阅读本次变更记录并确认新增配置已写明用途、来源和失败排查。
2. 使用 `git diff --cached` 检查完整暂存差异，不能只检查文件名。
3. 检查新增文件名以及高风险模式，如 `BEGIN PRIVATE KEY`、GitHub Token、OpenAI Key、AWS Key 和明显的密码赋值。
4. 运行仓库的 Gitleaks 门禁；无法运行时必须在变更记录中说明，并至少完成人工扫描。
5. 推送后查看 GitHub Actions；扫描失败时不继续下一阶段。

Gitleaks 位于推送 / PR 链路：checkout 获取完整历史后，扫描已经进入 Git 的内容。失败时先查看 Actions 注释和规则 ID，判断是真实凭据还是无权限的测试样例；误报只能用带原因、范围最小的配置排除，禁止为了绿灯关闭整个扫描。

## 泄漏响应

一旦真实密钥进入提交、日志或远程平台：

1. 立即在提供方轮换或吊销；仅删除文件不能消除风险。
2. 记录影响范围、暴露时间和受影响环境，检查使用日志。
3. 从当前版本移除密钥，并在必要时使用经过确认的历史清理流程；公共共享历史禁止擅自强推。
4. 新增变更记录和防复发测试，再恢复交付。

任何泄漏处置都不能把密钥原文复制到文档、Issue、提交信息或聊天汇报中。

## JWT 特别规则

- `AGENTFORGE_JWT_SECRET` 是运行时密钥，必须为至少 32 字节随机值的 Base64 表示。
- 仓库不提供可用于共享环境的默认密钥；本地示例值必须明确标记为仅开发用途。
- 生产、测试和本地环境使用不同密钥，轮换时允许旧 token 自然失效或主动终止相关环境。
- JWT 只携带最少身份和角色声明，不放密码、密钥或敏感业务内容。
