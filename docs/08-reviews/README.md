# 08-reviews: 代码审查中心

本目录保存 Pi 只读审查报告和 Codex 机器验证记录。历史报告只能作为排障线索，不能证明当前工作树通过。

## 审查流转机制

1. **触发时机**：Day 5 起，Codex 完成实现并亲自跑完测试后，一次性触发 Pi Agent 只读审核当前阶段 diff；不自动触发、不轮询。
2. **审查报告**：Pi Agent 读取当次交付的 `git diff`、相关代码与 Codex 已记录的测试证据，按照 `../templates/review-record-template.md` 格式生成审查报告。审查报告命名规范为：
   `YYYY-MM-DD-review-day-<X>.md`。
3. **修复与回填**：Codex 读取审查报告，对提出的问题做出技术研判：
   - 若采纳：Codex 实施修复并补充自动化测试，再由 Codex 重跑相关测试；必要时再做一次 Pi 只读复审；
   - 若误报或豁免：在第 3 节明确写出技术依据与原因；
   - 严禁盲目机械照改。
4. **接受门槛**：只有可复现的严重缺陷、代码无法运行、重大安全或数据一致性问题、真实冲突、架构边界破坏或明显偏离阶段目标才阻断交付。架构正确且可维护性、可扩展性足够时，纯风格、偏好或面向未来的优化建议可以记录但不要求返工。
5. **归档**：双方确认无阻断性问题后，将报告状态更新为 `RESOLVED`。
