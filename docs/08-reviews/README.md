# 08-reviews: 代码审查中心

本目录保存历史 Pi 审查报告和当前 Codex 机器验证记录。2026-09-05 起 Pi 已停用，历史报告只能作为排障线索，不能证明当前工作树通过。

## 审查流转机制

1. **触发时机**：Codex 每完成一个阶段并交付（或在阶段中断点），自动触发 Pi Agent 执行只读代码审查；实现进入验证门后，由 Pi 的受限验证会话执行测试。
2. **审查报告**：Pi Agent 读取当次交付的 `git diff`、相关代码与测试，按照 `../templates/review-record-template.md` 格式生成审查报告；验证报告还必须记录实际命令、退出码、测试数量、跳过项和清理结果。审查报告命名规范为：
   `YYYY-MM-DD-review-day-<X>.md`。
3. **修复与回填**：Codex 读取审查报告，对提出的问题做出技术研判：
   - 若采纳：Codex 实施修复并补充自动化测试代码，再由 Pi 执行验证，在报告第 3 节回填修复说明；
   - 若误报或豁免：在第 3 节明确写出技术依据与原因；
   - 严禁盲目机械照改。
4. **归档**：双方确认无阻断性问题后，将报告状态更新为 `RESOLVED`。

## 2026-09-05 生效：停用 Pi

用户已撤销 Pi 审查与测试授权。Codex 直接运行构建、格式和测试，核对机器产物并记录退出码、测试数量、失败、跳过与清理。旧 Pi 流程仅供历史追溯，不得启动 monitor、调用 Pi 或凭旧 PASS 自动推进。详见 docs/07-changes/2026-09-05-disable-pi-and-day1-day4-audit.md。
