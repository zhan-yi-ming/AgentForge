# ADR-0006：本机状态驱动的 Pi 审查循环

- 状态：Accepted
- 日期：2026-09-04

## 背景

提交后 Codex 必须停止，而 Pi 审查和修复复审需要跨多个 Codex 唤醒持续进行。仅用当前 HEAD 的轮询无法补审历史提交，也无法表达“待修复、复审第几次、人工接管”的状态。

## 决定

- 采用版本化阶段注册表保存已知历史交付的审查边界，采用本机 `.review-loop-state.json` 保存运行时状态。
- 审查报告是项目证据，保存并归档到 `docs/08-reviews/`；运行时状态、PID、日志和恢复信号不提交。
- `review-loop.ps1` 是 Codex 唤醒和 monitor 共用的唯一状态机；最多三次 `NEEDS_FIX`，第三次后进入 `HUMAN_REQUIRED`。
- Pi 只读审查，Codex 负责判断和实现；不允许脚本自动套用 LLM 补丁。

## 后果

- 好处：交付、审查、修复和人工接管都能跨会话追踪，历史 Day 1/Day 2 也可补审。
- 代价：需要在每个开发工作树启动 monitor，且本机状态丢失后可从报告和注册表重建为待审。
- 不采用：外部队列或数据库会超出 V1 的复杂度；让 Pi 写代码会破坏独立审查边界。
