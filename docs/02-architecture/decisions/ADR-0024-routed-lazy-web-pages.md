# ADR-0024：独立路由与按需加载 Web 页面

- 状态：Accepted
- 日期：2026-09-18
- 决策者：项目维护者

## 背景

现有 `App.tsx` 同时承载聊天、Wiki、Task 与整理视图，以局部布尔状态切换；URL 无法表达当前页面或会话，也让全部页面逻辑进入首屏代码。用户要求新页面均使用独立路由，并降低首屏加载负担。

## 备选方案

- 保持单组件与悬浮窗：改动小，但无法满足 URL、隔离和按需加载要求。
- 引入完整路由框架：导航能力成熟，但当前路由简单，新增根级依赖和锁文件会扩大变更与回归范围。
- 使用浏览器 History API 的小型路由层，并用 React lazy 页面边界：满足当前明确路径，避免新增根级依赖；需要自行处理 `popstate` 与未知路径。

## 决策

采用浏览器 History API 的小型路由层，解析固定路径 `/`、`/chat`、`/chat/:conversationId`、`/wiki`，页面视图分离为按需加载的组件。首阶段的 App 仍协调既有共享状态和 API 调用，后续按阶段把页面专属状态下沉；会话内容仅由 Chat 页面渲染。既有 Task 与 AI 整理面板也拆成按需加载的视图，避免 Markdown 渲染库进入初始包。新增页面必须声明新路径及独立页面组件，必要时再评估引入路由框架。

## 结果与取舍

可直接进入和刷新指定页面，按需加载控制首屏资源；需要测试浏览器后退、未知路径和 URL 会话作用域。Core API 仍是授权权威，路径 ID 不代表读取权限。
