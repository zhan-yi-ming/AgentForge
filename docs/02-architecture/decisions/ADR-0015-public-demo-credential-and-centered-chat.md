# ADR-0015：公开 Demo 凭据与居中对话入口

- 状态：Accepted
- 日期：2026-09-06
- 取代范围：ADR-0014 中“固定 Demo 密码不得进入公开仓库”的决策；ADR-0014 的流式协议和服务信任边界继续有效

## Context

AgentForge 的首要演示对象是 HR 与面试官。V1.2 把固定 Demo 密码限制在服务器私有 `.env`，安全性更强，但访问者必须通过额外渠道取得凭据；宽屏工作区又把 Wiki/Task 与聊天左右排列，使首次访问者难以识别核心体验路径。

用户明确要求把聊天置于视觉中心、加入新手引导，并采用一组可公开读取的固定 Demo 凭据。该凭据会出现在浏览器和公开仓库，因此不能再按秘密处理。

## Decision

1. 登录页与工作区采用居中单栏主内容。左侧只保留窄项目导航；Agent Chat 是主内容首个功能，Wiki、Task 与文本整理在下方纵向展开，不再与聊天组成左右主栅格。
2. 首次登录后显示轻量新手引导；浏览器只在 `localStorage` 保存完成标记，顶栏提供重新打开入口。
3. 固定 Demo 邮箱和密码作为**公开、无秘密属性的体验凭据**写入 Web 登录提示、生产示例与生成脚本。登录页提供一键填入，减少 HR 的理解成本。
4. 公开账号只能是普通 USER，只允许访问专用演示 workspace，并继续受项目隔离、每日 AI 配额、登录/API IP 限速和 HITL 保护。
5. 公开凭据不得复用于管理员、服务器维护、数据库、JWT、内部服务、模型 Provider 或包含敏感数据的环境。真正秘密仍只通过服务器私有配置提供。
6. 环境校验只对这组明确的公开 Demo 凭据放宽最短密码限制；任何其他固定 Demo 密码仍执行既有 12–72 字符规则。

## Alternatives

- **继续私下分发随机或服务器专有密码**：秘密边界更强，但 HR 无法独立进入，违背本次体验目标。
- **开放匿名体验**：避免显示密码，但需要新增匿名身份、配额、滥用防护与数据隔离模型，明显超出小分支范围。
- **在 URL 中携带凭据或自动登录**：步骤更少，但会把密码放入历史、日志或 referrer，风险更高，不采用。
- **只修改 CSS，不加引导**：无法解释 Wiki、Task、HITL 等能力，不能解决首次使用问题。

## Trade-offs

公开固定账号降低进入门槛，但任何人都可以登录，共享账号也不提供身份归属。风险通过低权限、专用无敏感数据 workspace、配额、限速和可重置性控制；它适合公开 Demo，不适合真实协作环境。

居中单栏强化核心对话路径，但页面会更长；Wiki、Task 和文本整理仍保留在同页下方，避免为本切片引入路由或复杂导航。

## Consequences

- 公开 Demo 密码出现在源码或扫描结果中不是秘密泄漏，但必须用明确常量名和文档说明避免误用。
- 固定账号被污染、锁定或滥用时，维护者可以重建该普通用户及 workspace；真正的服务密钥不受影响。
- V2 开发沿用此 UI 和 Demo 入口，但本决策不启动 V2-01，也不改变 V2 节点顺序。
