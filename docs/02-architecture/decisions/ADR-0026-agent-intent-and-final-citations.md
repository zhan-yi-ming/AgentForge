# ADR-0026：模型意图与完成回答引用分离

- 状态：Accepted
- 日期：2026-09-19
- 关联阶段：P3-04

## 背景

固定句式 planner 无法覆盖正常中文任务请求；现有 `sources` 由检索候选直接生成，候选不等于回答依据。流式 metadata 先于回答发出，无法在该时点判断最终引用。

## 决定

Python 可让已配置 LLM 在 retrieve 后独立产生结构化 Action Intent。它只使用当前请求与当前项目已授权的检索上下文；Pydantic/schema、动作白名单与目标版本检查先过滤模型输出。Java 保持 Action 的权限、风险、审批、审计和业务写入权威。无模型模式与明确命令保留确定性路径。

生成回答通过专用编号 `【来源1】` 等引用已授权检索来源；最终 sources 只由有效编号筛选，普通列表序号不能误当引用。同步 Chat 在返回前完成筛选；流式 metadata 不声称候选为引用，complete 才携带最终 sources，Java/Web/历史持久化使用 complete 结果。没有有效标注时 sources 为空，不猜测引用。

## 后果

模型模式增加一次规划调用与延迟；规划不可用或输出无效时不生成 Action，聊天回答仍可完成。模型漏标引用会使来源列表为空，这是避免错误归因的保守选择。流式 complete 的 sources 是向后兼容的新增字段；旧客户端仍可读回答，但不会得到最终来源。Java/Python 仍以现有内部认证与请求作用域隔离，模型不获得直接写入接口。
